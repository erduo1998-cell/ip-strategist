# 创作者档案 · Dossier

> **升级说明**：这是档案格式版本（schema_version 见文件顶部 frontmatter）。**1.8 → 1.9 变更**：新增建档诊断状态、六模块断点和首次建档核心字段；契约的 7 个机器字段和状态机不变。旧档案先备份，由 agent 针对性补问缺口，不伪造答案，不修改历史契约。

> **使用说明**：复制本文件为 `ip-dossier.md` 时保持 `onboarding_status: in_progress` 与 `onboarding_step: goal`，按 `references/11-建档诊断.md` 逐模块访谈。中断就保留断点；六模块达标、完整展示草案并获得用户一次明确确认后，才改为 `provisional`。档案仍分四区——**①底座区** / **②契约索引区** / **③数据快照区** / **④认知沉淀区**；建档状态是 frontmatter 基础设施，不新增主流程阶段。
>
> 档案是状态数据结构，不替代 `references/` 方法论。references 教「怎么做对」，档案记录「这个创作者现在在哪、卡在哪、验证了什么」。两者咬合：复盘的结论回流进档案的认知沉淀，档案的人设红线反过来约束下一条内容。
>
> **隐私提示：** 本文件含创作者敏感商业判断（定位、人设、变现方向、数据表现、对人认知等），请勿公开分享或提交到公共 git 仓库；建议同步在工作目录 `.gitignore` 中忽略 `ip-dossier.md` 与 `ip-contracts/`。

## 四、认知沉淀区

分两轨，别混。**「内容认知」**记这条钩子 / 骨架 / 选题打法管不管用——A 轨被验证的结论写进本区 A 轨，其中真正跨个体通用的判断由维护者在发版时人工 curated 进 `references/`（agent 不自动写公共 references）；**「对这个人认知」**记我对这个具体的人的判断、尤其在哪里被打脸——往个体走，只留本档、不外流。两轨各自三档，各自带验证次数。这是档案里最值钱的部分：A 轨让下一次决策站在已验证的打法上，B 轨让下一次看这个人更准——两者都让判断不必每次从头猜。

**升级门槛（统一阈值，两轨通用）**：同一判断被（不同内容 / 不同时间）验证 **≥3 次**，才写进本区并下重结论；不足 3 次的判断只能停在「待验证」桶。每条必须带「验证次数」字段，否则不升级。

### A. 内容认知（这条内容打法管不管用 · 写进本区，通用者由维护者 curated）

**✅ 已验证**（验证次数 ≥ 3 次，数据明确支持、可复用）：
- [一句话结论]｜验证次数：N｜依据：______
- [待填]

**❓ 待验证**（有猜想但样本不足 / 变量没控住，验证次数 < 3）：
- [一句话猜想]｜验证次数：N｜差什么数据：______
- [待填]

**❌ 已证伪**（数据明确推翻，别再踩）：
- [一句话结论]｜验证次数：N｜证伪原因：______
- [待填]

### B. 对这个人认知（我对他的判断 · 不外流 · 这才是越来越懂他的载体）

**✅ 已验证**（看人看准了，可复用）：
- [我对他的判断]｜验证次数：N｜依据：______
- 例：他的真瓶颈是镜头表现力而非选题｜验证次数：3｜依据：换表现力打法完播涨、连改三条选题不动

**❓ 待验证**（诊相刚下的对人赌注，落在这里等验证）：
- [我对他的判断]｜验证次数：N｜差什么：______
- 例：赌他卡在变现路径不清｜验证次数：0｜差变现数据

**❌ 已证伪**（看人看错了 · 最值钱的一档 · 必写原因）：
- [我原以为 X]｜验证次数：N｜证伪原因：______
- 例：以为他卡在选题→其实卡在表现力｜证伪原因：连续 3 条改选题无效，换表现力打法才动

> 填写指引：A 轨记内容打法对不对（「XX 类选题波赞比稳定」），B 轨记看人准不准（「以为他卡选题，其实卡表现力」）。两回事，分别归档，别混。B 轨的「已证伪」尤其别漏——被推翻的对人判断，是下一轮诊断最值钱的输入；只记 A 不记 B，等于内容方法论在涨、对这个人的理解没涨。
>
> **归档去向收敛为两个有实际容器的选项**：①进本区（A 轨或 B 轨，按验证次数分桶）；②提请维护者 curated 进通用方法论（可选，agent 不自动写 references）。**注意：A 轨（内容认知）被验证的结论写进本区 A 轨，其中真正跨个体通用的判断由维护者在发版时人工 curated 合并进 `references/01-定位与人设.md` + `references/02-选题方法论.md`；B 轨（对这个人认知）只留本档案、不外流，因为它只对这个个体成立，塞进通用文档会污染。**没有第三个虚浮去向。

### 选题库

选题按数据验证状态分三桶放，别混。每条复盘完的契约，对应的具体选题归进相应桶——这是进相的落地：让选题库随复盘自动进化，不是一锅端。

**扩** —— 已被数据验证跑得好的方向。同方向多出、变着花样出，把对的动作固化成习惯。

|------|
|  |

**砍** —— 已被证伪或持续没流量的方向。停掉别再踩，踩了也是重蹈覆辙。

| 选题 |
|------|
|  |

**测** —— 新冒出来、还没验证的方向。标待测，排队签新契约（见二、契约索引），用控制变量法各做几条让数据说话。

| 选题 |
|------|
|  |

> 空想一万遍，不如让数据跑一遍。扩和砍都得有数据撑腰——没数据的统统丢进「测」，别凭感觉就标扩。
