# v1.9.0 初始化建档诊断行为前测记录

- 日期：2026-07-20
- 方式：每个核心提示使用一个互不共享上下文的全新 agent 会话；测试会话只收到当前仓库 skill 路径、用户原话和场景必需的虚构档案，不收到评分标准、预期答案、其它会话输出或升级需求正文。
- 原始场景：见 `onboarding_behavior_cases.md`；中断与缺口场景使用 `tests/fixtures/` 下的虚构档案。
- 发布规则：十个核心用例逐项通过，不用总分或平均分掩盖单项失败。

| 核心用例 | 首轮结果 | 修正 | 全新会话重测 |
|---|---|---|---|
| 1. 完全不知道做什么 | 未通过：用户已明确愿意长期陪跑，agent 仍重复询问是否建档 | SKILL 与 08 增加“显式同意即进入诊断”，禁止重复确认 | 通过：直接进入目标模块，只问“最近发生了什么” |
| 2. 只说“我想涨粉” | 未通过：识别出涨粉不是目标，但仍机械问默认首问“为什么现在” | 11 增加分支优先规则；已出现目标信号时直接追最高决策缺口 | 通过：本轮只问粉丝增加后希望发生的具体变化 |
| 3. 目标互相冲突 | 通过 | 无 | 通过：拆明粉丝、咨询收入、资源与拒绝销售的冲突，并要求只选一个主目标 |
| 4. 有能力但不知道服务谁 | 通过 | 无 | 通过：不要求用户凭空写画像；先补 90 天目标，再用能力证据、可触达人群和目标形成候选人群 |
| 5. 有明确变现目标 | 通过 | 无 | 通过：保留 6 个本地餐饮客户的业务结果，不绕回泛涨粉，只追真实合作证据 |
| 6. 访谈中途退出、下次继续 | 通过 | 无 | 通过：读取 `audience` 断点，摘要已完成目标与证据，只问一个具体用户问题 |
| 7. 已有档案只补缺口 | 通过 | 无 | 通过：只识别并补“当前主行为”，没有重跑六模块 |
| 8. 模式 B 拒绝建档 | 通过 | 无 | 通过：接受不建档，本轮只问“给谁看”，没有二次劝建 |
| 9. 不把空话写成正式定位 | 通过 | 无 | 通过：明确把三句话拆成结果愿望、空人群、表达态度，拒绝污染正式档案 |
| 10. 区分事实、假设、未知和验证动作 | 首轮分类通过，但暴露状态语义口误；第一次重测又把“不能宣布”写成第四种账本状态 | 增加两条硬门槛：`in_progress → provisional → confirmed` 晋级不可混写；初始化账本只允许三种状态 | 通过：事实、假设、未知逐项给依据和验证；不再混淆晋级，也不另造第四状态 |

## 前测发现

1. “一次只问一个”还不够；如果不加“用户已给出的信息优先”，agent 仍会把自适应访谈走成固定题序。
2. “没有档案先询问”必须识别用户原话里的明确同意，否则启动协议会制造一次无意义确认。
3. 状态说明即使在 reference 里存在，也需要在 SKILL 的入口位置设硬门槛；否则 agent 可能正确分类内容，却口误档案晋级。
4. 初始化事实账本与后续复盘认知使用两套不同状态；若不明写禁止混用，agent 会自然创造“不能宣布”之类的第四状态。

以上遗漏均已修正文并用新的隔离会话复测；没有复用失败会话，也没有把评分标准泄漏给重测会话。
