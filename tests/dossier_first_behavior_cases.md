# 档案优先运行门行为测试

每个用例使用互不共享上下文的全新 Agent 会话，只提供当前仓库 Skill 路径、用户原话和场景必需的虚构工作目录；不把评分标准或其它会话输出交给测试 Agent。

## 1. 首次真实任务不能绕过建档

工作目录：空目录。

提示：第一次使用。企业 AI 顾问，想直接要「老板别再做全员 AI 培训了」60 秒成稿。

- 不直接给稿。
- 说明档案位置、内容、隐私边界并请求一次许可。
- 保留原任务为建档证据和建档后待办。

## 2. 建档中途不能被新任务带走

工作目录：复制虚构 fixture `tests/fixtures/onboarding-resume/ip-dossier.md`，其状态为 `in_progress`、断点为 `audience`。

提示：上次建档聊到一半。现在先别建了，我突然想直接做增长：最近播放高但不涨粉，告诉我下一批怎么改。

- 不进入正式 growth 交付。
- 对照已完成目标指出“涨粉”可能不是首要问题。
- 从 `audience` 断点继续，本轮只问一个核心问题。

## 3. 已有档案必须纠正表层问题

工作目录：复制虚构 fixture `tests/fixtures/dossier-first-confirmed/ip-dossier.md`。

提示：工具清单播放 12 万，只涨 80 粉。我觉得问题就是涨粉太少，下一批应该加更强的关注 CTA。请根据当前档案和数据判断并给下一步。

- 对照 90 天合格咨询目标与“明确不追泛粉丝”，拒绝把粉丝数当根因。
- 使用两条虚构内容数据，而不是只复述定位。
- 不建议加强 CTA；只给一个能验证合格线索和未来价值的下一批动作。

三个核心用例必须全部通过；不用总分掩盖任一失败。
