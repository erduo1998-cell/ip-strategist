# 增长层行为测试记录

## v2.1.0 Fresh 复测

- 日期：2026-08-17。
- 方式：使用一个全新 `confirmed` 虚构档案，以独立用户口吻请求 30 天增长与系列方案；测试 agent 未读取 behavior cases/results、测试预期、PR 文档或其他 agent 输出。
- 实际判定：通过。没有把问题重判成追粉或赌爆款，而是验证哪类风险场景能稳定带来目标用户的合格申请。
- 实际交付：形成《这句风险汇报，怎么改》内容项目；固定“原句 → 问题 → 四格改写 → 适用边界”，30 天 12 条只切换场景类型，并保留稳定承诺、主行为、主 IP 积累、业务角色、比较指标和续做/停止条件。
- 跨任务证据：定位、选题、脚本与增长四次独立请求持续继承同一目标时刻、同行前辈关系、当前/长期价值、“风险翻译官 + 四格白板”记忆资产和业务去向，未出现局部增长方案带偏长期方向。
- 覆盖边界：本轮直接覆盖内容项目和跨单条继承；下方五个 v1.8 核心用例是历史基线，本轮没有逐项重跑平台时效、零基础起号或 AI 工作流。

以上是 fresh-agent 行为证据；内容预算、单胶囊结构、摘要字段和系列表解析由 129 项 unittest 中的确定性测试另行验证。

## 通过依据摘要

- 播放不转粉：不单归因人设；逐项检查一次性价值、未来价值、主页、错误人群、识别点和原主目标；未知明确标注；下一批只改一个变量。
- 单条爆款做系列：输出稳定承诺、可变变量、连续机制、单集自足、主页承接与续/改/停条件。
- 零基础起号：不承诺粉丝量或一夜起号；处理真实资质与健康内容边界；区分稳定模型和发布战役；给出主目标、记忆资产、主页与验证窗口。
- 平台时效说法：传言先过事实门；事实卡包含平台、说法、来源类型、链接、发布日期、核验日期、适用范围、置信度和复查日；未证实部分不进入策略前提。
- AI 一键起号：AI 负责资料、发散、初稿和检查，人负责真实性、共情与最终判断；工作流止于待审发布包，不承诺爆款。

其余观察用例保留在 `growth_behavior_cases.md`，不替代以上发布门槛。
