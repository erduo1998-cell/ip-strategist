# 08 · 陪跑闭环与档案

## 开篇:这个维度在解决什么问题

前七份维度装的都是"怎么判一件事"——怎么判定位、怎么判选题、怎么判脚本。但创作者真正卡住的地方,很少是"判不出",是判完之后没人接住。今天判清楚了,明天打开新会话,agent 又从零问一遍定位;上周赌了一个选题方向,这周数据回来了,谁也不记得当初赌的是什么。单次咨询像急诊,看完就走;陪跑要的是家庭医生——记得病史、知道上次开了什么方、复诊时能对着上次的判断逐条查。

这份维度解决的就是这一件事:**怎么把零散的判断和动作,串成一条能跨会话接住的线。** 它不新增内容方法,只新增一套机制——让前面七份的方法,真正落进一个创作者的长期节奏里。三条心法贯穿全篇。

**一、关键原则靠 prompt 纪律落地,这是正解不是妥协。** "会话开始先读档案""有契约待复盘必须提醒""契约发布后不可改"这几条命门,靠 agent 守纪律执行。对一款开源、要多 agent 兼容、装上即用的 skill,prompt 纪律就是正解——不绑死在单一 harness 上,任何 agent 都能跑。把这几条焊进 hook 物理化,是多人协作、严防自欺的场景才需要的重武器,会绑死单一 harness、增加维护负担,本 skill 不走这条路。纪律会松吗?会。但解法不是上 hook,是把启动协议写得足够硬(见下文),让 agent 想漏都难。

**二、原始数据不进上下文,归因后的结论才进。** 一条视频后台几十个数字,原样塞进档案等于把噪音当记忆。档案不是数据仓库,是判断仓库。该存的是归因后的结论——"这条第八秒下滑的真因是第五六秒那句让观众反感的话"。原始数据粘进来只为当场归因,归因完留结论不留数字。塞满原始数字的档案,两三个月就没人读得下去。

**三、复盘是逐项验证每条判断,不是看一眼准不准。** "这次准不准"是个没法回答的问题。准,是哪几条准、准到什么程度;不准,是哪条偏了、往哪偏。复盘的标准动作是拿着当初的契约一条条对数据,标清楚每条是验证了、待验证、还是被证伪。只看总体感觉的人,复盘一百次也攒不下经验。

## 方法论骨架

### 一、四相工作流:陪跑的心法,不是检查表

陪跑的工作流叫四相——诊、契、行、盘。它继承诊断式五步的同一个精神:**按创作者当下卡在哪切入,不强制走完。** 带着明确选题来的人,直接进"行"补弹药;连定位都没想清的人,得先拉回"诊"。四相是地图,不是流水线。

它和单次诊断的区别只有一个字——**接**。诊完接契、契完接行、行完接盘、盘完接下一轮诊。每一相的产出都是下一相的输入,每一相的结论都写回档案。断在某一相的会话,下次打开能从断点接上。这是陪跑之所以叫陪跑的根本。

**诊:看创作者当下卡在哪。** 把账号现状、阶段、最近一批内容的数据摆出来,判断最该先动的那一件事。新用户还没有可执行底座时,诊相先按 `references/11-建档诊断.md` 完成初始化建档诊断;这不是新的主流程阶段,只是诊相的新用户分支。为什么成立:"我迷茫"谁也救不了,但被真实事实收窄的假设就能开始验证。日常诊相产出一段诊断结论与一条可被打脸的「对人赌注」,落进档案认知沉淀区 B 轨待验证。诊相对赌赌的是这个人,跟契相的内容赌注平行,不混。

**契:把诊断翻译成可验证的判断。** 这是最容易被跳过、却最不能跳过的一相。把诊断结论落成一条条将来能拿数据验证的判断——不是"你的开头有问题",而是"这批开头换成反差钩子,我赌前三秒留存会涨"。每条契约带三样东西:一个具体判断、一个赌注(命中什么、赢什么样、输什么样)、一个验证窗口(几条之后盘)。为什么成立:没有赌注的判断事后没法验证,等于没下过判断——"我觉得开头有问题"和"我赌反差钩子能让前三秒留存涨",复盘时完全是两件事。产出:一份带赌注的契约,落到 `ip-contracts/C-YYYYMMDD-NN.md`(由 `templates/contract-template.md` 复制);档案的契约索引区是只读视图,下次会话启动时从契约原件头部自动重建收录,不在这里手写登记。**模式A(陪跑)下默认不豁免**——哪怕只改一句文案,也留一句可验证的契约(为什么改、改完赌什么)。**豁免只有一种情形:模式B(单次咨询 / 纯诊断场景)**,不签契约、不建全套档案,只输出诊断结论,不强制留契约。不再用「纯诊断且不发内容且无判断」那类层层叠加 AND 的死条款——模式B 就是无条件轻量入口。本条与 SKILL.md 契相豁免一致,两边对齐到此。

**行:创作者执行,agent 按需补弹药。** 诊断和契约清楚了,这一相是落地的活——出选题、搭骨架、写逐字稿、改开头,按上游 01-04 的方法来。陪跑不是光说不练,每条契约得有对应动作去执行,否则盘什么都没得盘。产出:可直接用的弹药。跳过条件:创作者只要判断不要产出,或自己写、只要你盯一眼。

**盘:数据回来后逐条验证。** 创作者把数据粘进来,agent 不看总体播放量,拿着契约一条条对——这条验证了没、那条偏了没。为什么成立:不复盘的判断悬在空中,既不能当经验用、又占着认知带宽;只有被数据验过的判断,才配进档案的沉淀区。产出:每条契约的三档归档(已验证 / 待验证 / 已证伪),加归因结论写回档案。跳过条件:验证窗口没到(没到就不盘);样本不够 3 条同向,不拒盘但降级定性分析(置信度低、结论停待验证、不进认知沉淀区),≥3 条同向才是下重结论的门槛。

盘完,A 轨(内容认知)被验证的判断写进档案认知沉淀区 A 轨;跨个体真正通用、值得进 references 的判断,由维护者在发版时人工 curated 合并进 references/01、02(references 是只读通用方法论库,agent 不自动写公共 references),下一轮"诊"有了更厚的起点。这是闭环真正转起来的地方:**每一轮陪跑,都让档案厚一层。** 陪跑的价值不在某次判断多准,在于判断被接住、被执行、被验证——这个循环转起来,创作者才不是在原地打转。

### 二、进相:样本分档进化(第五相)

诊契行盘转一圈,盘完归档,闭环看似收口了。但还差最后一相——进。前四相是每次会话都在转的日常循环,进不是。进是样本攒够之后才触发的进化动作:把多次被数据验证的判断,从档案里提炼出来,固化成创作者自己的方法论。这一相不常走,但每走一次,认知就厚一层。

**心法只有一条:样本数决定一条结论能下多重。** 一条视频验证了某个判断,不代表它成立——偶然性太大。三五条都指向同一方向,开始有分量,但还不能下重结论。十几条反复指向同一个结论,再不总结就是浪费积累。少样本下重结论叫过拟合——等于掷三次硬币都是正面,就赌正面必出,荒唐程度一样。大样本还在凭感觉不总结叫欠拟合——攒了一柜子复盘数据,认知沉淀区却空着,等于光积累不提炼。进相要防的,就是这两个极端。

分档不是“N 条样本对应允许什么动作”的对照表(那是清单思维,这里不搞),是一种靠叙事和举例来校准的感觉:

冷启动期,手里只有三五条复盘样本,结论要轻——“这几条似乎指向一个方向,但样本太少,先记下、别当规律”。这时候最危险的是过早收敛:看两三条都对,就兴奋地总结成铁律,下一批数据直接打脸。纪律是多观察、少断言,把可疑的模式标成“待验证”,别急着固化。

复盘攒了几轮,某些判断开始反复出现——同一种开头连续几条稳定拉高前三秒留存,同一个选题角度连续几条都跑出流量。这时候该做的不是继续观望,是动手提炼:把这条反复被验证的判断,用一句话写进认知沉淀区(档案四区之一,下一节讲),注明「验证次数」。**提炼的门槛是同一判断被验证 ≥3 次,不是攒满十条复盘**——总复盘条数是噪音,同一判断的验证次数才是信号。这一步是进相的核心动作——把“数据反复支持的”翻译成“创作者自己的方法论”。

样本更厚之后,结论自然可以下得更重,但重结论也要标边界:这条在什么垂类、什么阶段、什么变量下成立?换一个场景还成立吗?好的方法论结论自带它的适用范围,不是放之四海皆准的废话。

**进相的触发标志很朴素:** 同一类判断,被数据验证 ≥3 次,且每次归因都指向同一个方向。这时候不动手提炼,就是白攒。触发后的动作也简单——一句话写进认知沉淀区,标“基于 N 次验证”+「验证次数」字段,下次诊断它就成了更厚的起点。

**两个极端都要防。** 冷启动期过早下重结论——三条就总结规律,和掷三次硬币都是正面就赌正面必出一样荒唐;成熟期样本充足却还在凭感觉不总结——攒了一堆复盘,认知沉淀区空着,等于光积累不提炼,永远在原地打转。判断自己卡在哪个极端很简单:看认知沉淀区的条数,和累计复盘条数成不成比例。盘了很多条却没沉淀几条,要么是过早收敛(每条都急着写,结果大半被后续推翻)、要么是欠拟合(攒着不总结)。

> **操作锚点(进相什么时候做什么)**
>
> 上面这一段是叙事和举例,是主;下面这组锚点是速查,不是死对照表。方向稳不稳定、经不经得起反向测试,才是最终判据——**锚点不是闸门**。
>
> - **3-5 条同向样本(样本条数锚点)**:开始有分量,可下轻结论,仍不重押。这是"样本条数",与下面的"验证次数"是两个概念,数字相近别混淆。
> - **同一判断被(不同内容 / 不同时间)验证 ≥3 次**:可提炼成认知,一句话写进档案认知沉淀区,标"基于 N 次验证"+「验证次数」字段;下重结论时同时标清楚适用边界(什么垂类、什么阶段、什么变量下成立)。**这是写入认知沉淀区的统一阈值(不是 10 条)**——没有「验证次数」字段的条目不升级、不沉淀。
> - **下重结论前做反向测试**:问一句"有没有哪条数据是反例、能不能解释掉"。解释不掉的反例,就是这条结论的边界,别装没看见。

**诚实标注:进相的燃料是复盘数据,断流即停。** 这一相的燃料来自两样东西——创作者把数据粘进来盘,以及契约待复盘时顶在前面的缺失提醒。创作者不盘、或盘得稀疏,样本就攒不起来,进相自然停转。这不是机制能补的缺口,是创作者自己要守的纪律。agent 能做的只是:每次复盘归档时顺手判断一句“这批样本够不够触发一次进相”,够了就提醒“这几条反复验证了 X,要不要提炼进沉淀”。提醒,不代替判断。

### 三、创作者档案:陪跑的记忆体

没有档案的陪跑是假的。每次会话打开第一件事是读 `ip-dossier.md`:**先扫 frontmatter 的 `onboarding_status` / `onboarding_step`**,再扫顶部『当前状态』header,然后读四区并扫 `ip-contracts/`。`in_progress` 必须从断点续访;文件存在不等于档案完整。文件不存在且用户尚未表态时先问"要不要先建个档";用户已明确愿意建档或长期陪跑则直接视为同意,不重复确认。随后创建 `in_progress` 档案并按 11 进入六模块自适应访谈,不得复制空模板后直接放行。用户拒绝则切模式 B,不再劝。

档案分四区,每一区存不同时间尺度的东西,千万别混。(另外两块是基础设施、不计入四区:顶部有『当前状态』header,记当前相 / 当前阶段 / 上次会话约定;底部有『元数据』,记 schema_version 与累计复盘条数。这两块是骨架不是判断,下面四区才是放判断的地方。)

**①底座区(带版本)。** 创作者的定位锚点——一句话人设、目标用户画像、内容支柱、变现锚点。这一区改得最慢,但每条都该能被最近的内容反推出来。底座是所有判断回去的锚,锚一漂后面全跟着漂。内容多来自 01 落地后的产出。**底座不是不能动,是动了要留痕**(同契约"发布即冻结+修订"):定位真该调时,记一句"改了什么、为什么、被哪条 B 轨(对这个人认知)的证伪触发"——这样底座从一次性锚定,变成随验证缓慢进化,而不是悄悄漂了没人记得(留痕落在 dossier 底座区的「底座修订留痕」表)。

**②契约索引区(只读)。** 这一区只存一张**索引表**,**不存契约原件**。契约是独立文件,放在工作目录的 `ip-contracts/` 下,每条契约一个文件,命名 `C-YYYYMMDD-NN.md`,由 `templates/contract-template.md` 复制而来。索引表四列:**编号 / 选题 / 状态(待发布 / 待复盘 / 已复盘 / 已废弃（已取消）) / 下次复盘日**——状态字段与契约原件头部一致。这张表是"行"相的待办看板,也是"盘"相的工作清单(逻辑上的"契约队列"就是它)。"已废弃"用于选题决定不发、方向被推翻等场景;已废弃契约不纳入复盘催办和待发布超期计算,但保留在 `ip-contracts/` 作为决策留痕。

工作流三条:(1) 每次签新契约 → 写一份 `ip-contracts/C-YYYYMMDD-NN.md`(契约原件头部是状态唯一可信源);索引区只读,不手写追加;(2) 每次会话启动 → 运行 `python3 <skill-path>/scripts/ip-check.py <工作目录> 3 --sync-index`,从原件头部原子重建索引,发生修改时保留备份;(3) 契约一旦发布即冻结,要改就新开一条、注明"修订自哪条、为什么改",原件留在 `ip-contracts/` 不动——历史即留痕。空了不代表没事干,代表所有判断都已收敛。

**③数据快照区。** 最近一两批内容的关键局部比值(波赞比、赞粉比、完播曲线异常点、分享量),加每条的归因结论。注意是归因后的结论加关键比值,不是后台截图。三周前的波赞比和今天对比,比任何"感觉进步了"都靠谱。

**④认知沉淀区(分两轨)。** 每次复盘后,被验证或证伪的判断提炼成一句话写进来——但分两轨,别混。**A 内容认知**:这条钩子/骨架/选题打法管不管用(如"反差钩子在我这个垂类,前三秒留存稳定比平铺高"),A 轨验证结论写进本档案 A 轨;跨个体真正通用的,由维护者发版时人工 curated 合并进 references/01、02(agent 不自动写公共 references)。**B 对这个人认知**:我对这个具体的人的判断、尤其在哪里被打脸(如"以为他卡选题,其实卡表现力"),只留本档案、不外流——这才是"越来越懂他"的载体;B 轨缺位,等于内容方法论在涨、对这个人的理解没涨。两轨各自三档(已验证/待验证/已证伪),各自带「验证次数」字段,只收被数据验证 ≥3 次的结论,不收"我觉得"。

读写规则朴素:会话开始读全文并运行索引同步,过程中按需改某一区,结束前写回。写回走原子替换,写失败保留备份。**并发写纪律(务实,不夸大):不承诺跨会话检测「档案是否被别处改过」;写前重读最新内容,写后告诉用户修改了几处。**原始数据只在当次"盘"的上下文里出现,归因完不留。发布时回填 `actual_publish_date`,状态转为"待复盘",并按 `actual_publish_date + review_after_days` 生成 `next_review_date`;已复盘或已废弃时清空 `next_review_date`。索引表只读,由脚本跟随原件重建。

### 四、数据缺失提醒:让复盘逃不掉

契约进了"待复盘"队列,意味着创作者答应过"这批发完会把数据拿来盘"。现实是大多数人不会主动拿来——不是赖账,是发完就忘了、或数据不好不想面对、或忙着做下一条顾不上。结果是契约越攒越多,全都悬在空中,复盘永远做不完。这是陪跑最常见的死法,比判断不准还致命。

解法是一条 prompt 纪律(靠 agent 每次会话守纪律执行,不依赖外部 hook):**每次会话的第一条回复,只要有契约待复盘,必须把提醒顶在最前面。** 格式是「⏰ 待复盘 N 条(最早一条日期 YYYY-MM-DD)」,放在回复开头,直到数据带来盘掉为止。这条提醒不解决创作者不面对的心理问题,它解决"agent 自己也忘了"的问题——只要每次都戳一下,创作者至少没法假装这事不存在。

陪跑里最贵的不是聪明的判断,是"那个一直没被验证的判断"——既不能当经验用,又占着认知带宽,还让创作者误以为自己在进步。提醒机制的存在,就是让悬空的契约尽快落地:要么盘,要么承认它还悬着,二选一。

### 五、复盘的标准动作:逐条验证,三档归档

"盘"是闭环的收口,做扎实了档案才厚得起来。标准动作四步,但记住这是动作顺序、不是检查清单——每步的目的是把判断验证清楚,不是走流程。当流程走,就退化成 07 反复警告的"凭感觉复盘"。

**第一步,粘数据。** 创作者把这批内容的关键数据粘进来(不足 3 条同向也可盘,但走降级定性、结论停待验证)。不全没关系,但局部比值要有——总体播放量意义不大(详见 07),波赞比、赞粉比、完播曲线异常点才是能动手的地方。

**第二步,逐条对契约。** 拿着契约队列里"待复盘"的每一条,一条条问:当初赌什么、数据支不支持。每条标三档之一——✅ 已验证(数据明确支持)、❓ 待验证(数据模糊、样本不够或变量没控住,留待下批)、❌ 已证伪(数据明确推翻)。标注必须引用具体数据,不许写"看起来还行"。验证是动作,不是印象。

**第三步,三档归档。** 已验证的提炼成一句话进认知沉淀区;待验证的退回契约队列,标注清楚差什么数据;已证伪的特别重要——写清证伪原因,因为被证伪的判断往往是下一轮诊断最有价值的输入。只记对的、不记错的,是复盘最大的自欺。归档的同一个动作里,A 轨验证结论只写进档案认知沉淀区 A 轨(agent 不自动改 references);真正跨个体通用、值得进通用方法论的判断,由维护者在发版时人工 curated 合并进 references/01、02。已证伪的,把那个方向在本档标注清楚别再踩;新冒出来但还没数据的方向,标成待测、排进契约队列。盘完归档,档案厚一层。

**第四步,更新累计复盘条数。** 档案里有一个计数:累计盘过多少条契约。数字本身不证明任何事,但它给创作者一个看得见的进度——陪跑是长跑,需要能看见自己跑了多远。

这一整套,把"我觉得这次还行"翻译成"这三条验证了、那条证伪了、原因是 X"。后者才是能复利的经验。契约的具体字段和归档格式,见 templates/contract-template.md。

## 判断要点与反模式

反模式比正面指导管用——下面这些坑,每一个都是陪跑半途而废的真实死法。

**凭感觉复盘,不归因。** 创作者把数据一粘问"这次怎么样"。不逼着对契约逐条验证,agent 很容易回一句"整体还不错,继续加油"。这种复盘做一百次也攒不下东西。归因才是复盘的全部——每条数据波动都要追到具体原因,追不到就不算盘完。"整体还行"是复盘里最废的四个字。

**拿单条视频来问怎么办。** 单条有偶然性,07 早就讲透。但在陪跑里它还有第二层危害:单条没法验证任何契约,只会让"待复盘"队列越积越虚。数据不够 3 条同向,降级定性分析、结论停待验证、不进认知沉淀区(不硬挡,但也不下重结论);进认知沉淀区、下重结论的统一门槛是「同一判断被不同内容/不同时间验证 ≥3 次」。拿单条硬盘当规律,盘出来的全是噪音。

**不建档案就硬陪跑。** 没有档案,agent 靠会话上下文硬记,几轮之后就记串了——把上周证伪的判断当下次诊断的前提,或把创作者根本没说过的定位当成既定事实。这种记忆错乱比不陪跑还危险,因为它看起来还在陪、还在给判断,实际上判断的地基已经飘了。宁可退化成单次咨询,也别装着在陪跑。

**复盘只盯播放量,不看局部比值。** 总体播放量波动因素太多,用它验证任何契约都是耍流氓。契约说反差钩子会涨完播,就看前三秒留存这条具体数据,不是看总播放涨没涨。盯错数据,等于用错的尺子量对的东西,量出一堆假结论。

**契约写完偷偷改。** 创作者(或 agent 自己)发现当初判断不太对,不动声色把契约改顺一点再回来"验证"。这是陪跑里最隐蔽的自欺——改完的契约当然容易验证,但彻底失去了复盘的意义。契约一旦写下就是历史,要改就新开一条、注明"修订自哪条、为什么改",旧的保留。诚实的证伪比漂亮的验证值钱一百倍。

**只记对的,不记证伪的。** 认知沉淀区只塞验证了的结论,证伪的悄悄丢了。结果是档案里全是"我对了",创作者看起来越来越准,实际上同样的错下次还会犯。证伪的判断必须留,而且要写清原因——成长真正发生的地方,不在那条验证了的判断里,在那条被推翻的判断里。

**把"盘"当走过场。** 创作者为应付提醒,随便粘点数据说"盘完了"。复盘不是任务,是闭环的命门。走过场的盘,等于在档案里写假数据,污染的是后续所有的诊断依据。宁可这批先不盘、让提醒继续顶着,也别交一份假复盘。

## 精选案例

案例是骨架的注脚。下面三个都用 07 已有素材,但从陪跑闭环的视角重述——看四相怎么转、档案怎么厚。

**一、守正出奇的完整闭环。** 某账号定位清楚但流量模型尚未跑稳，诊断是需要先建立可复现地基（诊）。契约落成：先铺一批七十分精准内容、控制变量，同时准备高潜实验；赌注是“主页形成连续价值后，高潜内容更容易被承接”。执行期团队反复想临时换方向，agent 用契约守住本批变量（行 + 提醒）。后来一条内容明显高于自身基线，也带动同定位存量内容被访问（盘：契约得到初步支持）。归因只写成“这个账号本轮支持先建地基再放大的顺序”，不把单个案例外推成普遍定律。下一轮诊有了更厚的起点。这个案例说明陪跑的真正价值：判断被接住、被执行、被验证，才会成为可用认知。

**二、完播曲线倒推,契约差点被错误证伪。** 某创作者一批视频完播曲线都在第八秒下滑,第一反应的契约是"第八秒内容有问题,要改第八秒"。盘的时候,agent 没直接按表面数据归档,而是倒推前两三秒——发现真因是第五六秒说了句让观众瞬间反感的话,人到第八秒才走。如果只看表面,这条契约会被错误标成"证伪"(改了第八秒也没用);倒推一步,契约修订成"真因在第五六秒",再一批验证成立。这个案例说明盘相的核心:验证不是机械对数据,是追到真因——数据指向 A,不代表 A 就是对的答案。数据是线索,不是判决书。

**三、控制变量测选题,让数据替犹豫拍板。** 某创作者在"口播讲观点"和"记录日常"两方向间反复犹豫(诊:方向不定)。契约落成:两方向各做五条,拍摄形式和状态几乎一样、只换方向;赌注是"数据会替你选"。执行完十来盘下来,A 方向整体流量明显更好,且创作者自己发现做 A 更顺手(盘:双向验证——数据加体感)。归档成认知:"这个垂类,口播观点优于日常记录"。犹豫了几个月的事,一次闭环拍板。这个案例说明陪跑最擅长解决的,就是那种"问谁都没用、只能让数据说话"的纠结——而能让数据真说话的前提,是当初把契约写成了可被数据回答的样子。

## 衔接

这份维度是"机制层",它自己不产生内容方法,只把前七份的方法装进一个能跨会话运转的壳里。

**承接上游 01-04:** 定位、选题、脚本、文案,是"诊"和"契"的弹药。没有 01 的定位锚点,"诊"无从判断卡在哪;没有 02 的选题方法,"契"落不成带赌注的判断;没有 03、04 的骨架和文案,"行"出不了能用的弹药。前四份解决"怎么判得准",这一份解决"判准之后怎么不被丢掉"。

**承接上游 07:** 复盘与执行是"盘"相的全部弹药。07 的分层模型、局部比值、控制变量、守正出奇,在这一份里被装进有契约、有提醒、有归档的流程——不再是"复盘完就忘",而是"每条判断都进档案、都被验证或证伪、都成为下一轮的起点"。07 教怎么盘,这份教怎么让盘逃不掉、盘完留得住。07 是内功,这一份是把内功练成日常的练功日程。

**承接上游 09(阶段与节奏)。** 阶段判断是"诊"相的关键输入——创作者卡在哪一相,很大程度由他处在 09 哪个阶段决定(起号期、稳定上升期、瓶颈期、爆款后续航各开不同的药)。

**与 templates 与 `ip-contracts/` 的关系:** `templates/dossier-template.md` 是档案的可填写模板(四区结构 + 累计复盘计数 + 只读契约索引表),`templates/contract-template.md` 是契约的可填写模板(五段式:判断与赌注 + 打法 + 可验证预期 + 回看约定 + 三档归档)。每次签契约时,把 `contract-template.md` 复制成 `ip-contracts/C-YYYYMMDD-NN.md`(每条契约一个独立文件,发布即冻结);dossier 里只留一张指向这些契约的只读索引(编号 / 选题 / 状态 / 下次复盘日)。这份讲机制心法,那两个讲具体字段长什么样。建档案时先读 templates 落第一版,日常陪跑时回来读这一份守纪律。
