# 内容复盘、归因与下一批动作

## 本任务解决什么

把已发内容的数据和当初判断对齐，定位损失、区分原因、更新判断，并给下一批只改一个变量的执行方案。复盘不是评价“好不好”，而是回答哪项假设被支持、证伪或仍未知。

## 最少输入

- 前置：已通过档案门并取得 review 摘要；缺档案或建档为 `in_progress` 时不得执行本胶囊，必须先完成 onboarding。
- 必需：要复盘的内容/批次、原目标或契约、可获得的数据与发布时间。
- 优先数据：曝光/来源、前段留存与异常点、完播、点赞/收藏/分享/评论、主页访问/关注、转化；只取与原目标有关的指标。
- 可假设：数据不全可做定性复盘，但必须列未知和证据强度，不估算后台数字。
- 必须追问：不知道当初要验证什么，且不同目标会产生相反评价；一次只问一个。

只打开摘要点名、用户要复盘的单个契约原件。没有原契约时先重建最小假设，不伪造“当初判断”。

## 决策路径

### 0. 先校正用户的归因

先对照档案目标、阶段、基线、契约和历史认知。用户说“算法限流”“开头不行”“选题错了”都只是候选解释；数据不支持时明确打回，不围绕错误归因优化。

### 1. 再还原实验

写清：目标人群、内容承诺、主验证目标、当初赌的需求/方案/结构、这批唯一变量、账号当时阶段。若同时变了选题、结构、人设和发布时间，明确“无法单因归因”，不要硬下结论。

### 2. 分层定位损失

按顺序查最上游异常：

1. 曝光/来源：推荐、搜索、外部入口是否异常；先排平台与样本问题。
2. 停留/前段：首屏承诺是否匹配目标人群，哪里开始持续掉。
3. 看完/当前价值：结构是否兑现，是否信息过载、旁枝泄漏或交付太晚。
4. 主行为分支：收藏、分享、评论、主页、关注或转化是否符合本条目标。
5. 后续承接：未来价值、主页连续性、系列与新粉留存是否接住。

总播放是结果，不足以直接归因。用账号自身同平台、同形态、同支柱的可比基线，不把别人的绝对数字当门槛。

### 3. 区分三类原因

- **平台/分发**：来源异常、规则变化或样本波动；时效说法需要一手核验。
- **内容**：需求覆盖、开头承诺、结构、表达、当前价值或 CTA 出现损失。
- **受众/账号**：错误人群、定位承诺、主页/系列不连续、阶段变化。

每个结论写支持证据和可能反例。单条可发现问题但不能证明规律；样本少就把结论降级为待验证。

### 4. 对契约判档

逐条判断：

- **已验证**：数据明确支持原假设。
- **待验证**：样本不足、数据缺失或变量混杂。
- **已证伪**：关键数据明确推翻原假设。

不偷改已发布契约。陪跑状态更新遵守七字段：发布时由 `待发布` 转 `待复盘` 并计算日期；盘完转 `已复盘` 且清空 `next_review_date`。若要修订，另开新契约并注明来源。

同一判断被不同内容/不同时间支持至少 3 次，且反向测试没有解释不了的反例，才可提炼进用户档案认知沉淀；标验证次数和适用边界。单次复盘不改公共 `references/`，真实用户数据不外流。

### 5. 下一批只改一个变量

从最上游损失选一个动作，写明：保持什么不变、只改什么、做几条可比样本、看哪个信号、何时判续/改/停。缺数据时，下一动作可以是补一个可观测信号，而不是盲目改内容。

## 交付物契约

默认输出一张复盘卡：

1. 一句话结论与证据等级。
2. 原目标/契约和数据完整度。
3. 损失发生在哪层，平台/内容/受众原因如何区分。
4. 哪项假设已验证、待验证、已证伪，各引一条关键证据。
5. 最大未知或反例。
6. 下一批唯一变量、保持项、样本与成功/失败信号。
7. 契约/档案最小写回说明。

不要给模糊总分，不用“整体不错继续努力”，不同时翻新多个维度，不把相关性写成因果。

## 失败与升级条件

- 只有单条且无基线：做定性定位，结论停在待验证。
- 数据来自不同平台/形态/阶段：分开比较，不混成一个平均数。
- 原始数据与用户描述冲突：列出冲突，请用户确认真源，不自行挑方便的版本。
- 契约状态损坏或 `ip-check.py` 报错：先修状态，不继续写回。
- 任务依赖平台最新规则：启动事实核验；查不到就保留未知。

## 交付前自检

- 是否先还原目标和控制变量，再看数据？
- 是否使用可比基线、定位最上游损失？
- 每个归因是否有证据、反例和强度？
- 单条/少样本是否被错误升级为规律？
- 下一批是否只改一个变量且有判定信号？
- 是否只开一个被点名契约，写回符合状态机和隐私纪律？
