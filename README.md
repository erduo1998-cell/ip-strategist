# ip-strategist · IP 打造策略师

**版本 v1.9.0**

**一个装进 agent 上下文就能用的开源 skill——把你的 AI 助手变成能持续陪跑创作者的 IP 教练。**

它给 agent 注入一套以耳总长期 IP 实战、影视导演、AI 咨询和创作者陪跑经验为核心的方法论，覆盖 **定位 → 选题 → 脚本 → 文案 → 表现 → 增长 → 变现 → 复盘** 全链路；再叠一层陪跑机制，让 agent 跨会话记住这个创作者是谁、卡在哪、上次的计划走到哪一步。装上之后，你得到的不再是"十个涨粉技巧"这种正确但无用的和稀泥，而是针对你这个号、这个阶段，给明确判断和明确下一步。

**适用人群：** 想做个人 IP 但不知道拍什么 / 已经在发但起不来 / 有内容没变现 / 想让 AI 持续陪自己打磨账号的创作者，以及替创作者做陪跑服务的操盘手。

**不适合谁 / 边界：** 本 skill 帮不到太多的人——

- 需要强督促 / 情绪支持 / 真人问责才能动起来的创作者（本 skill 不会追着你交作业）；
- 需要代操作广告账户、代管团队或代执行直播运营的场景（本 skill 可以给内容与变现策略判断，但不替你执行这些运营动作）；
- 期望"装上就变 IP 教练、零门槛自动产出"的用户（本 skill 给的是判断和方法论，内容还得自己想、自己拍）。

**和其它选项的差别：** 比通用 AI 助手（如 ChatGPT / Claude / 豆包裸用），本 skill 多了**一套 IP 方法论内核 + 跨会话陪跑档案**；比真人教练，本 skill **没有真人问责与专有数据**——判断是方法论推出来的，不是人盯人盯出来的。

> 术语白话：**skill** = 一个带 `SKILL.md` 说明文件的文件夹，塞进 agent 的技能目录，agent 就能自动识别并按里面的方法论干活，不用每次手动喊。

## 安装（三步，零门槛）

### 1. clone 仓库到 agent 的 skills 目录

Claude Code（推荐，用户级所有项目可用）：

```bash
mkdir -p ~/.claude/skills && git clone https://github.com/erduo1998-cell/ip-strategist.git ~/.claude/skills/ip-strategist
```

也可以放进某个项目的 `.claude/skills/`（只在该项目生效）。

**其它主流 agent 的 skills 目录路径：**

| Agent | skills 目录 | 说明 |
|-------|------------|------|
| Claude Code（确定支持） | `~/.claude/skills/`（用户级）或 `<项目>/.claude/skills/`（项目级） | 直接把整个 `ip-strategist/` 文件夹丢进去 |
| kimi-code（确定支持） | `~/.kimi-code/skills/` | 或临时指定：`kimi --skills-dir <父目录> -p "..."` |
| 其它 agent（Cursor / Windsurf 等） | 未验证 | 这两家目前**没有公开的 skills 目录自动发现机制**，本 skill 不臆测其路径，请自行查阅官方文档适配；任何遵循 `SKILL.md` frontmatter 约定的 agent 原则上都能用 |

确定支持的只有 Claude Code 及任何遵循 `SKILL.md` frontmatter（`name` + `description` 两个字段）约定的 agent；其余平台未在本仓库验证，自行适配。

### 2. 验证装好了

开一个新会话，对 agent 说一句：

> 读取 ip-strategist 的 SKILL.md 并复述四相。

agent 能答出"诊 / 契 / 行 / 盘"四相，就说明 skill 已被正确识别加载。skill 靠 frontmatter 里的 `name` + `description` 自动触发，后续不用显式调用，直接用自然语言提问即可。

### 3. 首次使用：完成建档诊断

推荐直接在创作者的私有工作目录对 agent 说：

> 我愿意长期陪跑，帮我建一份 IP 档案。

agent 会先创建 `in_progress` 档案，然后通过目标、证据、用户、价值、商业、执行六个模块做自适应访谈。**一次只问一个核心问题**；中断会记住当前模块，下次从断点继续。完成后先给你看完整 v0.1 草案，分开已确认事实、暂定假设、未知、依据和验证方式；你一次明确确认后才写入 `provisional` 档案。后续核心方向获得内容、用户或业务证据支持并再次确认，才晋级为 `confirmed`。

需要手动初始化时也可以复制模板：

在创作者的私有工作目录执行：

```bash
cp ~/.claude/skills/ip-strategist/templates/dossier-template.md ip-dossier.md
```

> **手动复制只是初始化，不等于建档完成。** 模板会保持 `onboarding_status: in_progress` 和 `onboarding_step: goal`；仍要让 agent 完成六模块诊断。`templates/contract-template.md` 和 `templates/weekly-plan-template.md` 由 agent 在需要时从 skill 安装目录读取，无需手动复制。
>
> **隐私安全提示：** `ip-dossier.md` 以及后续自动生成的 `ip-contracts/` 会记录创作者的定位、人设、变现方向、数据表现、对人判断等敏感商业信息。默认加入工作目录的 `.gitignore`，不要上传到公开仓库；确需用 Git 同步时，只使用访问受控的私有仓库，并优先加密备份。

**没有档案也能用：** 检测不到 `ip-dossier.md` 时，agent 会先问是否建档。你拒绝就切模式 B，诊断 / 选题 / 脚本 / 文案能力保留，不签契约、不跨会话写回。若直接要内容但方向明显不清，agent 会轻量问「给谁看 / 希望看完做什么 / 凭什么由你讲」，一次一问；仍不清时只产出显式假设的探索稿。

踩坑了？看 [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)。

## 最小启动提示词（手动压制）

如果你用的 agent 没有自动加载 skill、或自律不足老漏启动步骤，把下面这段话直接贴进会话开头，强制它先跑检查再对话：

> 你现在扮演 ip-strategist（IP 打造陪跑教练）。请严格执行以下最小启动协议：
> 1. 判定模式A/B：若工作目录已存在 ip-dossier.md 且默认模式为A，按模式A（陪跑）处理；用户声明本次按B，则按B轻量处理。
> 2. 模式A 下，先运行 `python3 <skill-path>/scripts/ip-check.py [工作目录] 3 --sync-index` 做预检并从契约原件安全重建索引。
> 3. 若出现「错误」级问题，先修复再继续；若出现「警告」级问题，向用户声明并由用户决定是否继续；若仅有「提醒」级问题，进入正题但带出提醒。
> 4. 读取 ip-dossier.md 的 `onboarding_status / onboarding_step`、当前状态与 ip-contracts/；`in_progress` 从断点续访，已完成档案有核心缺口时只补缺口。
> 5. 无档且用户同意陪跑时，读取 `references/11-建档诊断.md`，创建 `in_progress` 档案并进入六模块访谈，不得复制空模板后放行。
> 6. 按本次任务读取对应 references/；新建档草案和契约草案都是完整展示后只做一次明确确认，不重复确认。

也可以把 `ip-check.py` 配置成会话启动命令，让检查从「agent 记不记得」变成「入口必执行」。详见 [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)。

## 它能做什么

**策略与内容生产：**
- **账号定位诊断**——这个号现在有没有定位、定位站不站得住、目标用户到底是谁
- **人设与内容支柱设计**——通常 3 条内容主干，每条都能独立产出内容
- **选题策划与诊断**——用"需求 + 方案双向奔赴"的方法出选题，判断一个选题值不值得赌
- **视频脚本骨架**——钩子、结构、情绪点、反差观点的排布
- **口播逐字稿**——按骨架写成可直接念的稿子
- **镜头前表现力与镜头语言**——给意图和认知原则，不替剪辑工具干活
- **增长单元与系列设计**——诊断播放不转粉，明确主验证目标、未来价值、记忆资产、系列结构和起号发布战役
- **内容策略与变现路径**——不只管做内容，还管内容怎么变成钱
- **内容复盘诊断**——已发内容哪里出了问题，下一条怎么改

**陪跑机制（跨会话的那只手）：**
- **陪跑建档**——为创作者建一份档案，把每次会话的判断、契约、复盘沉淀进去，下次接着用，不用从零讲背景
- **初始化建档诊断**——从真实经历和证据出发，完成目标排序、战略取舍和可验证的 v0.1 暂定档案
- **签发布前的判断契约**——内容发布前，先和创作者对齐"这条赌的是什么需求、赢面多大、发完回收什么数据来验证"
- **引导数据复盘与归因**——内容发完后，对照当初的契约回收数据，看赌对了没、偏差在哪、下一条怎么改

**不做的（交给对应工具）：**
- 视频剪辑、后期制作、字幕轨、节奏拼接 → `jianying-editor`、`video-use`、剪映、CapCut、Premiere、达芬奇
- 视觉动效、B-roll、转场特效、信息图动画 → `hyperframes`、`remotion`

**一句话划界：** 负责"分镜意图与文案"这两端的脑力活，不负责把意图变成画面的手艺活。

## 四相工作流：每次会话的主循环

每次会话处于四相中的一相。agent 会先扫档案看你在哪一相、上次走到哪，再切入。

```
诊 → 契 → 行 → 盘
看卡在哪   签判断契约   动手做内容   发完对账归因
```

- **诊**：看清这个创作者/账号当前卡在哪——有没有定位、目标用户是谁、最该先动什么。多问多听，不急着给答案。
- **契**：内容发布前签一份判断契约——赌什么需求、赢面多大、失败长什么样、发完回收什么数据验证。几乎不跳过。
- **行**：真正动手做内容。定位、选题、脚本、逐字稿、变现路径全在这一相发生，按需调用。
- **盘**：内容发完回收数据，对照契约归因——赌对了没、偏差在哪、下一条怎么改。

四相是**每次会话的活跃主循环**，不强制走完，切入点永远是"当下卡在哪一相"。结束前 agent 会和你约定两件事：下次回哪一相、回收什么数据——这是陪跑能跨会话延续的锚。

## 四阶段：账号的长期生命周期（别和四相搞混）

四相是"每次会话怎么过"，四阶段是"一个账号一辈子怎么走"。两者是两个层面，档案里分别存"当前相"和"当前阶段"两个字段。

- **起号期**：从 0 开始，核心是快速验证定位、积累第一批样本。
- **稳定上升期**：有了一批数据和稳定产出，核心是把节奏固化、识别哪类内容能持续。
- **瓶颈期**：增长卡住，核心是诊断是真瓶颈还是该换方向。
- **爆款后续航**：一条爆了之后怎么接住流量、怎么把偶然变成可复现。

阶段识别与阶段内节奏把控的方法论见 `references/09-阶段与节奏.md`。

## 两种语气（对内 vs 对外）

agent 说话有两种语气，**搞混会出两种灾难**：

- **对内语气 · 对创作者说话**（讨论定位 / 策略 / 诊断 / 复盘）：敢下判断、不和稀泥、锋利是本分。
- **对外语气 · 写对外内容**（帮创作者写给观众的口播稿 / 文案 / 选题外壳）：代入创作者人设，守建档时定下的**人设红线**，语气走 04 的「语气指南」。

切换点就一句话：**这内容是给创作者看的，还是给观众看的。** 一条会话里可能反复切换。

> 注意：「语气（对内 / 对外）」和「建档模式（模式 A / B）」是两回事。前者管怎么说话，后者管要不要走陪跑档案 + 契约——别因为两个标签都带"模式"就混用。

## 脑力活全链路

```
定位 → 选题 → 脚本 → 文案 → 表现 → 变现 → 复盘
 01     02     03     04     05     06     07
```

这里的"全链路"指的是**脑力活全链路**（定位 → 选题 → 脚本 → 文案 → 表现 → 变现 → 复盘），**剪辑 / 后期 / 动效交给专门工具**（见前文「不做的」）。每个环节都有对应弹药，agent 按任务类型按需读取。**表现层（05）**是镜头前的表达与镜头语言认知，不是后期剪辑。

## 十二个维度弹药库

`references/` 目录下有**十二个维度文件（00-11）**，是 agent 针对不同任务按需调用的弹药，不必每次全读：

- **00 心法与反模式** —— 五条底层心法的展开和最常见的踩坑姿势，所有判断的地基
- **01 定位与人设** —— 差异化人设提炼、内容支柱搭建的方法论
- **02 选题方法论** —— 需求倒推和"需求 + 方案双向奔赴"的具体打法
- **03 脚本骨架** —— 钩子到收口的骨架、情绪四点的排布
- **04 口播文案** —— 把骨架变成口语的写法，和具体的语气特征（含「语气指南」）
- **05 表现力与镜头** —— 镜头前的表达和镜头语言（给的是意图，不替剪辑工具干活）
- **06 变现路径** —— 常见变现线的判断和路径规划
- **07 复盘与执行** —— 复盘的维度和日常执行节奏的设计
- **08 陪跑闭环与档案** —— 陪跑闭环的运转机制、跨会话档案的数据结构与复盘契约
- **09 阶段与节奏** —— 起号期 / 稳定上升期 / 瓶颈期 / 爆款后续航四阶段的识别与阶段内节奏把控
- **10 增长与系列** —— 主验证目标、当前/未来价值、关注三路径、系列引擎、账号记忆、起号战役与平台事实门
- **11 建档诊断** —— 六模块自适应访谈、目标排序、证据账本、断点续访、v0.1 完成门槛与模式 B 三问微诊断

## 快速开始（一条可验证路径）

不想读完整方法论，先跑起来再说：

1. **1 份 v0.1 暂定档案**——模式 A 先做六模块建档诊断；不会一次扔给你二十道题，会从真实经历逐问收窄。
2. **1 个最小可执行假设**——明确哪些是事实、假设和未知，只选第一批要验证的方向。
3. **1 条判断契约 + 1 份内容**——内容发布前写清赌什么、回收什么数据，再生成可执行稿件。

跑完这条路径，你拥有的不是看起来很完整的最终定位，而是一份能立即开始验证的暂定档案、一份可复盘契约和一份可执行内容。

## 使用示例

装好之后，直接用自然语言提问，agent 会根据上下文自动触发本 skill：

- "我做企业 AI 咨询，想做个人 IP 但不知道拍什么。"
- "帮我看下这个选题值不值得赌：[选题内容]。"
- "帮我把这个选题写成 40 秒的口播稿。"
- "我发了 20 条视频没起色，帮我复盘下问题在哪。"
- "三条教程播放和收藏都不错，但几乎没人关注，帮我定位损失并设计下一批验证。"
- "我有一条爆款，别只列相似标题，帮我提取稳定承诺并做成系列。"
- "我的内容支柱怎么搭？我擅长 AI 落地和企业咨询。"

一段完整的"首次到来 → 建档 → 签契约 → 出脚本 → 复盘"示例对话见 [docs/示例对话.md](./docs/示例对话.md)。

## 关于方法论来源

核心方法论来自耳总本人长期从事 IP 定位、内容策划、影视导演、AI 咨询和创作者陪跑过程中形成的个人经验、判断框架与案例复盘。v1.8 增长层还结合了公开行业讨论中关于关注行为与系列内容的可迁移问题，并重构为可被契约验证的增长框架；具体来源边界见 `references/10-增长与系列.md`。仓库不照搬第三方课程或作品，也不把外部观点去除来源后重新署名。

公开案例只保留支持方法论判断所需的信息，并去除客户、创作者与合作方的身份识别信息；未经许可，不公开真实姓名、账号、联系方式和敏感商业数据。行业公共事实或需要归因的公开观点保留真实来源，不改变原作者署名。

需要注意：仓库内的人设锚点（`references/定位锚点-示例.md`）是**虚构示例**，照抄格式即可，**用户需基于自身真实信息自建**，不要套用示例里的任何人物设定。

署名：**耳总**。

## 运行测试

仓库自带一组针对 `scripts/ip-check.py` 的单元测试。本地运行：

```bash
python3 -m unittest discover tests -v
python3 -S -m unittest discover tests -v
```

可选安装 PyYAML 以增强 frontmatter 解析能力（不装也能跑）：

```bash
pip install pyyaml
```

CI 还会额外执行仓库级检查与语法编译：

```bash
python3 scripts/ip-check.py . 3
python3 -m py_compile scripts/ip-check.py
```
